- 👋 Hi, I'm Amber Williams — Senior Technical Writer, Liquibase

I write developer documentation that help users move fast and build with confidence that people actually enjoy using. 
At Liquibase, that means CLI reference docs, changelog and
schema-change documentation, and release notes for a product whose entire job
is tracking *what changed, when, and what you need to do about it* — which is
the same problem I'd want to solve for API partners: docs and change
communication as one connected surface, not two separate jobs.

## What I own

- **All documentation on docs.liquibase.com** — including CLI & Command reference docs written for developers who are debugging 
a failed migration at 2am, not browsing.
- **Changelog & release notes** — every release ships with what changed, why
it matters, and what action (if any) is required before upgrading.
- **Migration & upgrade guides** — versioned, breaking-change-aware docs for
teams moving between major versions.

## How I work

- **Docs as a product, not an afterthought.** I track support ticket themes, 
documentation feedback, and LLM.md analytic improvements and use it to prioritize rewrites,
not just new content.
- **Style guide steward.** I maintain the style guide and internal editorial standards 
so docs read as one voice regardless of who drafted the first pass.
- **AI in the workflow.** I use Claude to draft our first pass of release notes 
from PR and Jira descriptions which I then edit for clarity and accuracy. 
I use Claude to automate first passes on conceptual and task based articles and I pass Jira tickets into Claude 
to be sure no feature is missed in the documentation.
